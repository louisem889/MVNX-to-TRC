# mvnx-to-trc

Convert **Xsens MVNX** recordings to **OpenSim TRC** marker files, and check the result in a 3D viewer.

* Built for recordings exported from **Xsens MVN** (Analyze or Animate): full body, MVNX version 4.
* Every marker is computed from the recording's own Xsens skeleton, using the person's calibrated body dimensions. Nothing needs to be calibrated or trained.
* **Checks every file before converting it**: damaged files, files not written by Xsens MVN, missing data and inconsistent skeletons are rejected with an explanation.
* Batch-converts whole folders. Only needs Python and numpy.
* Includes a self-contained 3D viewer (a single offline HTML file) that overlays the Xsens skeleton and the TRC markers.

## Installation

```bash
git clone <this repository>
cd mvnx-to-trc
pip install -r requirements.txt        # numpy
```

Requires Python 3.8 or newer. On Windows you can also use the drag-and-drop helpers (see [Windows helpers](#windows-helpers)).

## Quick start

```bash
# convert one file (writes recording.trc next to it)
python mvnx_to_trc.py convert recording.mvnx

# convert a folder into an output folder, and create a 3D check viewer per file
python mvnx_to_trc.py convert path/to/recordings -o path/to/output --viewer

# only check files, without converting
python mvnx_to_trc.py check path/to/recordings
```

## Output

The `.trc` is tab-separated, in **millimetres**, in **OpenSim axes (Y up)**. MVNX is Z-up in metres, so the axes are mapped as:

| TRC | MVNX |
|---|---|
| X | x |
| Y | z |
| Z | −y |

The frame rate comes from the MVNX, and the time column uses exact frame times. If the recording has dropped frames, the real timestamps are kept.

### Marker sets

`--markers trc46` (default) writes 46 markers:

| Group | Markers | How they are computed |
|---|---|---|
| Joints | `PelvisCenter`, `LHip`, `RHip`, `LKnee`, `RKnee`, `LAnkle`, `RAnkle`, `LShoulder`, `RShoulder`, `LElbow`, `RElbow`, `LWrist`, `RWrist` | the Xsens joint centres |
| Head | `Nose`, `LEye`, `REye`, `LEar`, `REar` | the Xsens landmarks |
| | `c_head` | Xsens joint `jC1Head` |
| Trunk | `c_neck` | Xsens joint `jT1C7` |
| | `c_spine0`–`c_spine3` | points along the Xsens spine (pelvis → C7/T1) at 9.3 %, 29 %, 49 % and 82 % of its length |
| | `Neck`, `Thorax` | offsets from C7/T1 in the T8 segment frame |
| Arms | `LAcromion`, `RAcromion` | the Xsens landmarks |
| | `LOlecranon`, `ROlecranon`, `LCubitalFossa`, `RCubitalFossa` | behind and in front of the elbow joint |
| Hands | `LIndex`, `LIndex3`, `LPinky`, `LPinky3`, `RIndex`, `RIndex3`, `RPinky`, `RPinky3` | fixed positions in the hand frame |
| Feet | `LHeel`, `LBigToe`, `LSmallToe`, `RHeel`, `RBigToe`, `RSmallToe` | fixed positions in the foot frame |

For markers without an Xsens landmark, positions are scaled by the person's own segment lengths. The constants were measured on reference TRC files of this marker set and agree between different people to within about 1–2 %. Xsens does not track fingers without gloves, so the finger markers move rigidly with the hand.

`--markers xsens` writes every anatomical landmark and joint centre in the MVNX instead: 106 points for a full-body recording, e.g. `pRightASI`, `pLeftLatMalleolus`, `jRightKnee`. This set is useful for scaling standard OpenSim models.

## File checks

Each file is checked before conversion. `python mvnx_to_trc.py check <files or folders>` runs only the checks.

**Rejected** (the file is skipped; a batch carries on with the next file):

| Problem | Detected by |
|---|---|
| Damaged or incomplete file (e.g. an interrupted copy) | the XML cannot be parsed |
| Not an MVNX file / empty file | the root element is not `<mvnx>`, or there is no content |
| **Not written by Xsens MVN** | missing Xsens namespace `http://www.xsens.com/mvn/mvnx`, or a comment saying the file was generated by another tool (e.g. a video pipeline). `--force` converts it anyway |
| Missing data | positions/orientations not exported, segments of the 23-segment full body missing, landmark points missing (old MVNX version) |
| Corrupt values | frames with the wrong number of values, NaN/infinite values, invalid quaternions |
| Inconsistent skeleton | each joint computed from the parent segment must coincide with the child segment's origin. Real Xsens data agrees to about 0.1 mm (toes up to about 20 mm); files with joints up to 150 mm apart, or a median gap above 20 mm, are rejected |

**Warnings** (the file is converted):

* no Xsens `securityCode` element (the file may have been edited);
* dropped frames (gaps in the timestamps; the real times are kept);
* a skeleton slightly less consistent than normal Xsens output;
* an unusual body height in the calibration (outside 1.2–2.3 m);
* a configuration other than `FullBody`;
* pelvis speed above 10 m/s (possible glitch);
* very short recordings.

The checks do not use the person's height or other body dimensions to decide whether a file comes from Xsens. The origin check relies on how Xsens MVN writes the file: its namespace, security code and comment.

## Validation

Tested on a real Xsens recording (21,848 frames at 60 Hz). Angles computed from the TRC markers were compared with the joint angles Xsens itself stores in the MVNX:

| Quantity | Agreement |
|---|---|
| Knee flexion | correlation 0.998–1.000, about 1° difference |
| Elbow flexion | correlation 0.993, 2–5° constant offset (Xsens reports a 3D Euler angle) |
| Trunk inclination | correlation 0.998 |
| Segment lengths | constant to ±0.04 mm |
| Heel/toe markers during Xsens foot contact | 47–54 mm above the floor (by marker definition) |
| Joint markers vs Xsens joints (viewer) | 0.00 mm |

## 3D check viewer

```bash
python mvnx_trc_viewer.py recording.mvnx [recording.trc] [--fps 30] [-o check.html]
python mvnx_to_trc.py convert recording.mvnx --viewer       # during conversion
```

It writes `<trc name>_viewer.html` and opens it in the browser. The page has no external dependencies and works offline. With `convert --viewer`, the viewer is created during conversion without reading the MVNX twice, and the browser is not opened.

**What it shows:**
* Xsens joint centres, bones and (optionally) landmarks, together with the TRC markers.
* A line from each TRC marker to its Xsens counterpart:
  * **exact** pairs (joints, pelvis, neck and head joints, nose, eyes, ears, acromions) should be about 0 mm and are coloured green, yellow or red against the threshold;
  * **nearest** pairs (markers with no Xsens equivalent) are drawn grey, because a constant offset is expected.
* A table with the distance now and the mean and maximum over the whole recording. The statistics use every frame.
* Click a marker to plot its distance over time.

**Controls:** drag to rotate, right-drag to pan, scroll to zoom, space to play or pause, arrow keys to step.

By default the viewer plays at most 30 fps (`--fps 0` shows every frame). Very long recordings are thinned further to keep the HTML under about 60 MB.

## Command reference

| Command | Purpose |
|---|---|
| `convert <files or folders> [-o DIR] [--overwrite] [--markers trc46\|xsens] [--viewer] [--viewer-fps N] [--rate HZ] [--force]` | Check and convert MVNX to TRC |
| `check <files or folders>` | Only run the file checks |

## Windows helpers

* `convert_all.bat`: double-click it to convert every `.mvnx` in its folder into `converted\`, or drag files onto it. It asks whether to also create viewers.
* `view.bat`: drag an `.mvnx` (and optionally its `.trc`) onto it to open the viewer.
